# Digital Ruble Wallets

Микросервис учёта цифровых кошельков клиентов банка. HTTP API принимает сведения от платформы цифрового рубля (ЦР), хранит кошельки и их жизненный цикл, простая web-страница предназначена для работы оператора.

## Стек

- .NET 10, ASP.NET Core Web API;
- Entity Framework Core 10 и SQLite;
- HTML, CSS и vanilla JavaScript.

## Запуск

Требуется `.NET 10`.

Из корня репозитория:

```powershell
dotnet run --project src/Api
```

- UI: <http://localhost:5195>
- API: <http://localhost:5195/api>

При первом запуске в `Development` приложение применяет миграции, создаёт `src/Api/digitalrub.db` и добавляет демонстрационные данные.

## Предметная модель

### Клиент

| Поле | Ограничения |
| --- | --- |
| `Id` | внутренний `Guid`, PK |
| `Mid` | обязательны, `string(100)`, уникальный межсистемный идентификатор |
| `FullName` | обязательное ФИО, `string(100)` |
| `DigitalRubleParticipantId` | необязательный, `string(100)`, уникальный, если задан |

Клиент может иметь много кошельков. Реализация считает идентификатор участника ЦР постоянным: его можно задать один раз, а повторная отправка того же значения допустима, другого — конфликт.

### Кошелёк

| Поле | Ограничения |
| --- | --- |
| `Id` | внутренний `Guid`, PK |
| `ClientId` | обязательный FK на клиента |
| `Code` | обязательный `string(100)`, глобально уникальный |
| `Status` | `Prcs`, `Actv`, `Blck` или `Clsd`, хранится строкой |
| `AccountNumber` | необязательный `string(20)`, устанавливается только один раз |

При создании допустимы только `Prcs`, `Actv` и `Blck`. Активным кошелёк считается, если имеет статус `Prcs`, `Actv` или `Blck`. `Clsd` финальный и неактивный. У одного клиента может быть только один активный кошелёк.

| Текущий статус | Допустимый новый |
| --- | --- |
| `Prcs` | `Actv` |
| `Actv` | `Blck` |
| `Blck` | `Actv`, `Clsd` |
| `Clsd` | нет |

Номер счёта нельзя заменить другим. В реализации он также сделан глобально уникальным.

## Модель данных

```text
Clients (1) ------> Wallets (N)

Clients
  Id                         Guid, PK
  Mid                        string(100), NOT NULL, UNIQUE
  FullName                   string(100), NOT NULL
  DigitalRubleParticipantId  string(100), NULL, UNIQUE

Wallets
  Id             Guid, PK
  ClientId       Guid, NOT NULL, FK -> Clients.Id
  Code           string(100), NOT NULL, UNIQUE
  Status         string(4), NOT NULL
  AccountNumber  string(20), NULL, UNIQUE
```

Связь использует `Restrict`: кошелёк не должен остаться без владельца.

```text

```

## API

JSON-статусы передаются строками в camelCase: `"prcs"`, `"actv"`, `"blck"`, `"clsd"`. Числовые значения enum не принимаются.

### Список клиентов

```http
GET /api/clients
```

Ответ `200 OK`:

```json
[
  {
    "mid":"MID-001",
    "fullName":"Иванов Иван Иванович",
    "digitalRubleParticipantId":"DRPARTICIPANT-001"
  }
]
```

### Кошельки клиента

```http
GET /api/clients/{mid}/wallets
```

Ответ `200 OK`:

```json
[
  {
    "code":"WALLET-001",
    "status":"actv",
    "accountNumber":"41111110000000000001"
  }
]
```

Неизвестный клиент — `404 Not Found`.

### Синхронизация данных от платформы ЦР

```http
PUT /api/platform/wallets
Content-Type: application/json
```

```json
{
  "mid": "MID-002",
  "digitalRubleParticipantId": "DRPARTICIPANT-002",
  "walletCode": "WALLET-002",
  "status": "prcs",
  "accountNumber": "41111110000000000002"
}
```

`mid`, `digitalRubleParticipantId`, `walletCode`, `status` обязательны. `accountNumber` необязателен. Сервис ищет клиента по `mid`, проверяет уникальность идентификатора участника ЦР, затем:

1. Создаёт кошелёк, если у клиента нет активного.
2. Либо обновляет активный кошелёк, если код совпадает с переданным.
3. Применяет только разрешённый переход статуса и может установить ещё не заданный счёт.

Успех — `204 No Content`.

### Изменение существующего кошелька

```http
PATCH /api/platform/wallets/{walletCode}
Content-Type: application/json
```

Нужно передать хотя бы одно из полей:

```json
{
  "status":"blck",
  "accountNumber":"41111110000000000002"
}
```

Успех — `204 No Content`.

| Код | Значение |
| --- | --- |
| `400` | не прошла валидация DTO: обязательные поля, длина, значение статуса, пустой `PATCH` |
| `404` | не найден клиент или кошелёк |
| `409` | нарушено бизнес-правило: неверный переход, второй активный кошелёк, смена счёта, дублирующий идентификатор |
| `500` | непредвиденная ошибка, внутренние детали не раскрываются |

## Web-интерфейс

Страница на `/` позволяет загрузить клиентов, выбрать клиента, увидеть его кошельки, изменить разрешённый статус, назначить ещё не заданный номер счёта и увидеть сообщения API.

## Демонстрационные данные

| MID | ФИО | Кошельки |
| --- | --- | --- |
| `MID-001` | Иванов Иван Иванович | `WALLET-001`, `Actv`, со счётом |
| `MID-002` | Петрова Анна Сергеевна | `WALLET-002`, `Prcs`, без счёта |
| `MID-003` | Сидоров Алексей Олегович | `WALLET-003-OLD`, `Clsd`, со счётом. `WALLET-003`, `Actv` |
| `MID-004` | Смирнова Елена Викторовна | Нет |

## Проверка

Коллекция проверяет чтение данных, `404`, жизненный цикл `Prcs -> Actv -> Blck -> Clsd`, первое назначение счёта, недопустимый `Actv -> Clsd` (`409`), повторную смену счёта (`409`) и пустой `PATCH` (`400`).

## Принятые допущения

- Клиенты уже существуют в банковской системе. API не создаёт и не редактирует их.
- Код кошелька уникален глобально.
- Номера счёта уникален глобально.
- Идентификатор участника ЦР после первого назначения неизменяем.
- При синхронизации другого кода для уже активного кошелька возвращается конфликт, а не создаётся второй активный кошелёк.
- Можно задавать счет для закрытого кошелька.
