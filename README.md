# Digital Ruble Wallets

Full-stack-приложение для банковских операторов и администраторов. Операторы находят клиентов, просматривают их цифровые кошельки и выполняют операции с кошельками. Администраторы управляют учётными записями операторов.

## Возможности

### Оператор

- Поиск клиентов по ФИО или MID.
- Просмотр идентификатора участника цифрового рубля и кошельков клиента.
- Назначение или изменение идентификатора участника цифрового рубля.
- Создание и синхронизация кошелька клиента.
- Изменение статуса кошелька и однократное назначение номера счёта.

### Администратор

- Просмотр списка учётных записей.
- Создание учётных записей операторов.
- Блокировка и разблокировка операторов.

Вход доступен по email и паролю или через VK ID. Пользователь может привязать VK ID к своей учётной записи и впоследствии использовать его для входа.

| Часть | Технологии |
| --- | --- |
| Backend | C#, .NET 10, ASP.NET Core Web API, Entity Framework Core 10, ASP.NET Core Identity |
| Хранение данных | PostgreSQL |
| Frontend | React 19, TypeScript, Vite 8, TanStack Query |

## Архитектура

Backend разделён на четыре проекта:

- **Domain** — сущности клиента и кошелька, а также бизнес-правила.
- **Application** — сценарии использования и абстракции доступа к данным.
- **Infrastructure** — Entity Framework Core, PostgreSQL, Identity и реализации репозиториев.
- **Api** — HTTP API, аутентификация и авторизация, обработка ошибок и композиция приложения.

Frontend организован по Feature-Sliced Design: `app`, `pages`, `widgets`, `features`, `entities`, `shared`. Для HTTP-запросов используется общий клиент, а TanStack Query управляет загрузкой данных и обновлением кеша после операций.

## Запуск Docker-деплоя

Docker Compose запускает PostgreSQL, backend API и Caddy. Caddy обслуживает frontend и проксирует `/api/*` к backend. API не публикуется наружу отдельным портом. Для этого сценария нужен домен, направленный на сервер: Caddy автоматически получает и обновляет TLS-сертификат для настроенного `APP_HOST`.

1. Скопируйте `.env.example` в `.env`.
2. Задайте значения для своего окружения. Не используйте примерные значения из `.env.example` для реального деплоя.
3. Запустите приложение из корня репозитория:

```powershell
docker compose up --build -d
```

Основные переменные `.env`:

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_PASSWORD` | Пароль пользователя PostgreSQL. |
| `APP_HOST` | Домен приложения, направленный на сервер и используемый Caddy для HTTPS. |
| `AllowedOrigins__0` | Origin frontend, например `https://app.example.com`; должен соответствовать адресу приложения. |
| `ADMIN_SEED_ENABLED` | Включает создание начальной учётной записи Admin при инициализации базы. Установите `true`, если нужно создать администратора. |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_DISPLAY_NAME` | Email, пароль и отображаемое имя начального администратора. |
| `PLATFORM_API_KEY_HASH` | Base64-кодированный SHA-256-хеш ключа Platform API. Секретный ключ в открытом виде хранить в конфигурации backend не нужно. |
| `Authentication__VkId__ClientId`, `Authentication__VkId__ClientSecret` | Данные приложения VK ID для входа и привязки аккаунта. |

Проверка доступности API: `https://<APP_HOST>/health`.

Остановка контейнеров с сохранением данных PostgreSQL:

```powershell
docker compose down
```

Удаление контейнеров вместе с данными PostgreSQL:

```powershell
docker compose down -v
```

> Команда `down -v` удаляет volume базы данных и все сохранённые в нём данные.

## Локальная разработка

### Требования

- .NET 10 SDK.
- Node.js и npm.
- PostgreSQL, доступный по строке подключения backend.

### Настройка backend

Задайте строку подключения `PostgresConnection` в `backend/Api/appsettings.Development.json` или через переменные окружения. Для локального PostgreSQL пример строки подключения:

```text
Host=localhost;Port=5432;Database=digitalrub;Username=digitalrub;Password=<ваш-пароль>
```

Запустите API из корня репозитория:

```powershell
dotnet run --project backend/Api
```

Стандартный адрес API: `http://localhost:5195/api`. В Development миграции базы данных применяются при запуске. При необходимости их можно применить вручную:

```powershell
dotnet ef database update --project backend/Infrastructure --startup-project backend/Api
```

### Настройка frontend

В папке frontend скопируйте .env.example в .env

В отдельном терминале из корня репозитория:

```powershell
cd frontend
npm ci
npm run dev
```

Vite запускает frontend по адресу `http://localhost:5173`. Указанный в `frontend/.env.example` `VITE_API_URL` соответствует стандартному адресу локального API. Backend разрешает этот origin для разработки.

## Бизнес-правила кошелька

- У клиента может быть несколько кошельков, но только один активный одновременно.
- Активными считаются кошельки со статусами `Prcs`, `Actv` и `Blck`; `Clsd` — финальный неактивный статус.
- Допустимые переходы статусов:

| Текущий статус | Допустимый новый статус |
| --- | --- |
| `Prcs` | `Actv` |
| `Actv` | `Blck` |
| `Blck` | `Actv`, `Clsd` |
| `Clsd` | — |

- Номер счёта можно назначить только один раз. Заменить его нельзя.
- Создать кошелёк можно только для клиента без активного кошелька.

Backend проверяет бизнес-правила и права доступа; frontend отображает доступные пользователю действия и результаты API.

## API

Базовый URL при локальном запуске: `http://localhost:5195/api`.

### Аутентификация — `/auth`

| Метод | Endpoint | Назначение | Доступ |
| --- | --- | --- | --- |
| `POST` | `/auth/login` | Вход по email и паролю; при успехе устанавливает cookie-сессию. | Без авторизации |
| `POST` | `/auth/logout` | Выход и завершение cookie-сессии. | Требуется вход |
| `GET` | `/auth/me` | Получить данные текущего пользователя и его роли. | Требуется вход |
| `GET` | `/auth/vk-id/login` | Начать вход через VK ID; перенаправляет пользователя на  авторизацию через VK. | Без авторизации |
| `GET` | `/auth/vk-id/login-callback` | Callback VK ID, завершающий вход и перенаправляющий пользователя во frontend. | Вызывается VK ID |
| `GET` | `/auth/vk-id/link` | Начать привязку VK ID к текущей учётной записи. | Требуется вход |
| `GET` | `/auth/vk-id/link-callback` | Callback VK ID, завершающий привязку аккаунта. | Требуется вход |
| `DELETE` | `/auth/vk-id` | Отвязать VK ID от текущей учётной записи. | Требуется вход |

Если VK ID не привязан к учётной записи, вход через него не выполняется. Redirect URI для callback необходимо настроить в приложении VK ID в соответствии с адресом backend.

### Оператор — `/operator`

Маршруты доступны пользователям с ролью `Operator` или `Admin`:

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/operator/clients` | Получить список клиентов. |
| `GET` | `/operator/clients/{mid}/wallets` | Получить кошельки клиента. |
| `PUT` | `/operator/clients/{mid}/participant-id` | Назначить или изменить ID участника цифрового рубля. |
| `PUT` | `/operator/clients/{mid}/wallets` | Создать или синхронизировать кошелёк клиента. |
| `PATCH` | `/operator/wallets/{walletCode}` | Изменить статус и/или назначить номер счёта. |

### Администратор — `/admin`

Маршруты доступны только пользователям с ролью `Admin`:

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/admin/users` | Получить список учётных записей. |
| `POST` | `/admin/users/operators` | Создать учётную запись оператора. |
| `PATCH` | `/admin/users/{userId}/block` | Заблокировать пользователя. |
| `PATCH` | `/admin/users/{userId}/unblock` | Разблокировать пользователя. |

### Platform API — `/platform`

Для интеграции платформы предусмотрены `PUT /platform/wallets` (создание или синхронизация кошелька) и `PATCH /platform/wallets/{walletCode}` (изменение статуса и/или назначение номера счёта). Эти маршруты не используют Identity-сессию: запрос должен содержать `X-Api-Key`. Ключ проверяется backend по SHA-256-хешу, настроенному через `PLATFORM_API_KEY_HASH`. Frontend операторов эти маршруты не вызывает.

Статусы кошелька в JSON передаются строками camelCase: `"prcs"`, `"actv"`, `"blck"`, `"clsd"`. Ошибки валидации возвращаются с кодом `400`, отсутствие сущности — `404`, конфликт с бизнес-правилом — `409`; непредвиденные ошибки возвращаются как `500` без внутренних деталей. В Development OpenAPI доступен по адресу `http://localhost:5195/openapi/v1.json`.

## Ограничения

- Создание и редактирование клиентов через API не предусмотрено. Клиенты загружаются в Development при инициализации базы данных.
