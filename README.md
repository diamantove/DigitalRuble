# Digital Ruble Wallets

Full-stack-приложение для банковских операторов: просмотр клиентов, управление участниками цифрового рубля и управление жизненным циклом цифровых кошельков.

## Быстрый старт

### Переменные окружения

Перед запуском создайте файл `.env` в корне проекта из файла `.env.example`, задайте:

```env
POSTGRES_PASSWORD=12345
```

### Запуск в Docker

Из корня репозитория:

```powershell
docker compose up --build
```

После запуска приложение доступно по адресу `http://localhost:8080`.

- Caddy раздаёт frontend и перенаправляет запросы `/api/*` в backend.
- API напрямую наружу не публикуется.
- Проверить доступность API можно по адресу `http://localhost:8080/health`.

Чтобы остановить контейнеры и сохранить SQLite-данные в Docker volume:

```powershell
docker compose down
```

Для полного сброса данных вместе с volume:

```powershell
docker compose down -v
```



## Обзор

Приложение состоит из одностраничного React-приложения и ASP.NET Core Web API. Интерфейс предоставляет собой поиск по клиентам, просмотр их кошельков и операции оператора: назначение идентификатора участника, создание кошелька и изменение его данных.  
API отвечает за бизнес-правила и хранит данные в SQLite.

## Предметная модель

### Клиент

| Поле | Ограничения |
| --- | --- |
| `Id` | внутренний `Guid`, PK |
| `Mid` | обязательны, `string(100)`, уникальный межсистемный идентификатор |
| `FullName` | обязательное ФИО, `string(100)` |
| `DigitalRubleParticipantId` | необязательный, `string(100)`, уникальный, если задан |



### Кошелёк

| Поле | Ограничения |
| --- | --- |
| `Id` | внутренний `Guid`, PK |
| `ClientId` | обязательный FK на клиента |
| `Code` | обязательный `string(100)`, глобально уникальный |
| `Status` | `Prcs`, `Actv`, `Blck` или `Clsd`, хранится строкой |
| `AccountNumber` | необязательный `string(20)`, устанавливается только один раз |

При создании допустимы только `Prcs`, `Actv` и `Blck`. Активным кошелёк считается, если имеет статус `Prcs`, `Actv` или `Blck`. `Clsd` финальный и неактивный. Клиент может иметь много кошельков, но только один активный кошелёк.

| Текущий статус | Допустимый новый |
| --- | --- |
| `Prcs` | `Actv` |
| `Actv` | `Blck` |
| `Blck` | `Actv`, `Clsd` |
| `Clsd` | — |

Номер счёта нельзя заменить другим.

## Возможности

- Просмотр и поиск клиентов по ФИО или MID.
- Просмотр идентификатора участника цифрового рубля и кошельков выбранного клиента.
- Назначение или изменение идентификатора участника цифрового рубля.
- Создание кошелька для клиента, у которого нет активного кошелька.
- Изменение статуса кошелька только в рамках разрешённого жизненного цикла.
- Однократное назначение номера счёта с защитой от последующей замены.
- Отображение в интерфейсе ошибок валидации и нарушений бизнес-правил API.

## Архитектура

Backend организован по принципам Clean Architecture.  
Domain содержит бизнес-правила и не зависит от внешних слоёв.  
Application содержит сценарии использования и абстракции доступа к данным.  
Api отвечает за HTTP и является точкой композиции приложения  
Infrastructure реализует доступ к данным через EF Core и SQLite, используя абстракции, объявленные в Application

```text
                      React (frontend)
                            |
                       HTTP / JSON
                            |
                            v
                  ┌───────────────┐
                  │   Api         │
                  │ backend/Api   │
                  └───────┬───────┘
                          │
            ┌─────────────┴─────────────┐
            │                регистрация зависимостей
            v                           v
┌────────────────────────┐    ┌────────────────────────┐
│ Application            │    │ Infrastructure         │
│ backend/Application    │    │ backend/Infrastructure │
└───────────┬────────────┘    └──────────┬─────────────┘
            │                            │
            v                            │
┌────────────────────────┐               │
│ Domain                 │◄──────────────│
│ backend/Domain         │               │
└────────────────────────┘               │
                                         |
                                         v
                                       SQLite
```

- **Domain** содержит поведение `Client` и `Wallet`: правила активного кошелька, допустимые переходы статусов и неизменяемость номера счёта.
- **Application** координирует сценарии получения клиентов, изменения идентификатора участника, синхронизации и обновления кошельков через абстракции репозиториев.
- **Api** предоставляет HTTP endpoints, валидирует контракты запросов, настраивает CORS и сериализацию JSON, а ожидаемые исключения преобразует в ответы `ProblemDetails`.
- **Infrastructure** реализует абстракции репозиториев через EF Core и содержит `ApplicationDbContext`, миграции и инициализацию демонстрационных данных.

Проект `Api` является точкой сборки приложения: он подключает Infrastructure для регистрации конкретных EF Core-сервисов, а Application зависит только от необходимых ему абстракций.

### Структура frontend

Frontend организован по принципам `Feature-Sliced Design`.  
Код разделён на слои app, pages, widgets, features, entities и shared, каждый из которых отвечает за свой уровень приложения.

```text
frontend/src/
├── app/        точка входа, провайдеры и глобальные стили
├── pages/      готовые экраны приложения, которые объединяют компоненты и функции в единое целое
├── widgets/    секции интерфейса: список клиентов, информация о клиенте и таблица кошельков
├── features/   действия: назначение ID, создание и изменение кошелька
├── entities/   типы клиентов и кошельков, запросы и форматтеры
└── shared/     HTTP-клиент и общие UI-компоненты/утилиты
```

API-модули features используют общий клиент на базе `fetch`. TanStack Query загружает клиентов и кошельки, а после мутации инвалидирует соответствующий запрос, чтобы интерфейс получил актуальные данные API.

### Локальный запуск без Docker

### Требования

- [SDK .NET 10](https://dotnet.microsoft.com/download)
- Node.js и npm

### 1. Настройка frontend

Из корня репозитория создайте локальный файл окружения Vite:

```powershell
Copy-Item frontend/.env.example frontend/.env
```

В `frontend/.env.example` указан адрес API для разработки:

```text
VITE_API_URL=http://localhost:5195/api
```

Оставьте это значение при использовании стандартного профиля запуска backend.

### 2. Запуск backend

Выполните из корня репозитория:

```powershell
dotnet run --project backend/Api
```

### 3. Запуск frontend

В отдельном терминале:

```powershell
cd frontend
npm ci
npm run dev
```

По умолчанию Vite запускает клиент на `http://localhost:5173`. Политика CORS backend явно разрешает этот адрес.

## Конфигурация и база данных

Backend читает именованную строку подключения `SqliteConnection` из `backend/Api/appsettings.json`:

```json
{
  "ConnectionStrings": {
    "SqliteConnection": "Data Source=digitalrub.db"
  }
}
```

`digitalrub.db` создается относительно рабочей директории процесса.

В Development миграции применяются автоматически при запуске приложения. При необходимости миграции можно применить вручную:

```powershell
dotnet ef database update --project backend/Infrastructure --startup-project backend/Api
```

## Обзор API

Базовый URL API в стандартном профиле запуска: `http://localhost:5195/api`.

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/clients` | Возвращает клиентов, отсортированных по ФИО. |
| `GET` | `/clients/{mid}/wallets` | Возвращает кошельки клиента. |
| `PUT` | `/clients/{mid}` | Назначает или изменяет идентификатор участника цифрового рубля. |
| `PUT` | `/platform/wallets` | Создаёт или синхронизирует активный кошелёк существующего клиента. |
| `PATCH` | `/platform/wallets/{walletCode}` | Изменяет статус кошелька и/или назначает номер счёта. |

Статусы кошелька передаются в JSON строками camelCase: `"prcs"`, `"actv"`, `"blck"` и `"clsd"`.

Ошибки валидации возвращаются как `400`, неизвестные клиенты или кошельки — как `404`, конфликты бизнес-правил и ограничений хранения — как `409`. Непредвиденные ошибки возвращаются как `500` без внутренних деталей. В Development API также публикует OpenAPI-документ по адресу `http://localhost:5195/openapi/v1.json`.

Для ручной проверки API импортируйте в Postman [DigitalRubleWalletsAPI.postman_collection.json](postman/DigitalRubleWalletsAPI.postman_collection.json).

## Примечание

- Клиенты добавляются при инициализации Development-базы; их можно получать и назначать им ID участника через API. Endpoints для создания или редактирования самих клиентов отсутствуют.
